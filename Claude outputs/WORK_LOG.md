# 루미 몬스터즈 (별빛의 씨앗) 작업 기록

Phaser 3 + Vite + TypeScript 클라이언트, Node 서버, Firebase 로그인 구조의 몬스터 수집 농장 RPG 작업 내역입니다.

## 1. 맵과 월드

- 별빛 마을과 바람골을 3단 구조(테라스, 옆 절벽, 언덕, 계단)로 재구성했습니다.
- 대륙과 섬 리그 구조로 바꿨습니다. 등대곶에서 배를 타고 가면 왕관 시티에 닿습니다.
- 길은 2~3구간으로 나뉘고, 체육관은 마을 끝에 배치했습니다. 모든 마을에 여관을 넣었습니다.
- 맵 생성 후 워프 검사(bad 0)와 도달성 검사(issues 0)를 통과했습니다.
- 소품(등불, 벤치)이 길 위에 놓이지 않도록 `tidyProps()`를 추가했습니다.
- 길목 트레이너는 길 옆 풀밭에서 길을 향하도록 배치했습니다.

## 2. 게임플레이

- 이동은 타일 단위로 바뀌었고, 점프 턱(ledge)과 뒤로 밀림(bump) 처리를 추가했습니다.
- R 키로 휴대폰, M 키로 지도를 열고, Tab 감정표현 입력 버그를 고쳤습니다.
- 발소리 볼륨을 조정했고, 기절 처리는 없앴습니다.
- 패배하면 가장 가까운 마을에서 부활합니다. 여관에서 쉴 수 있습니다(500G).
- 트레이너 레벨은 플레이어 레벨에 맞춰 조정됩니다.
- 도구에는 내구도와 등급(구리, 철, 별)을 붙였습니다.
- 실내 창문은 시간대에 따라 밤낮이 바뀝니다.
- 도감은 120종으로 늘렸습니다. 7개 타입 × 5라인 × 3단계 진화 구조이며, 진화 레벨은 `shared/data/creatures.json`의 `evolves` 필드에 있습니다.
- 새 BGM 7곡(숲, 해변, 설원, 사막, 섬, 여관, 도전)을 추가했습니다.

## 3. 스토리와 UI

- 열다섯 살 생일 선물로 엄마가 휴대폰을 주는 장면을 넣었습니다. 라이벌은 엄마와 대화한 직후 등장합니다.
- 휴대폰은 접히고 펼쳐지는 애니메이션을 넣었습니다. 홈, 지도, 버그 신고 앱이 있습니다.
- 대화창에는 벡터 SVG 초상을 처음 넣었다가, 어색하다는 의견에 따라 AI 일러스트 로딩 경로로 바꿨습니다.
- 모바일에서는 가로 화면 양손 조작(십자키, 달리기, A/B, 휴대폰, 지도, 감정표현)을 지원합니다. 세로로 들면 가로 전환 안내가 뜹니다.

## 4. 서버와 멀티플레이어

- 서버를 모듈로 나눴습니다. `index.ts`, `hub.ts`, `admin.ts`, `config.ts`, `auth.ts`, `storage.ts`로 분리했습니다.
- 전송 방식을 WebSocket(ws)에서 Socket.io로 바꿨습니다. 서버는 `Conn` 인터페이스로 전송을 추상화했습니다.
- 클라이언트 서버 주소는 `client/src/net/serverUrl.ts`에서 정합니다. 우선순위는 `?server=` 파라미터, `VITE_SERVER_URL`, 같은 호스트 2567 포트 순입니다.
- `/health` 경로를 추가했고, CORS는 `CLIENT_ORIGIN` 환경변수(쉼표 구분)로 허용합니다.
- 관리자 기능은 `kdy20716@gmail.com` 계정만 쓸 수 있습니다. 서버에서 Firebase ID 토큰을 검증하고 이메일 인증 여부도 확인합니다.
- 관리자 명령은 사용자 목록, 신고 처리, 킥, 밴, 이동, 아이템 지급, 골드 지급을 포함합니다. 모든 명령은 감사 로그에 남습니다.
- 버그 신고 기능을 추가했습니다. 쿨다운과 최대 길이 제한이 있습니다.
- `give` 명령에서 `__proto__` 같은 아이템 ID가 통과하던 문제를 `hasOwnProperty` 검사로 막았습니다.

## 5. 배포 설정

- 프론트엔드는 Vercel, 백엔드는 Azure에 배포하는 구조입니다.
- Vercel에는 `VITE_SERVER_URL`을 설정하고, Azure에는 `CLIENT_ORIGIN`을 설정해야 합니다.
- Azure App Service는 WebSocket을 켜야 합니다.
- `vite.config.ts`에 `envDir: '..'`를 넣어 프로젝트 루트의 `.env`를 읽도록 했습니다.
- `.env.example`을 만들었고, `.env`는 `.gitignore`에 넣었습니다.
- `start-game.bat`은 `package.json`이 바뀌면 `npm install`을 다시 실행합니다.
- README와 ROADMAP을 갱신했습니다.

## 6. 일러스트 파이프라인 (Gemini)

- `shared/data/illust.json`에 인물 52명의 성격, 포즈, 표정 정보를 넣었습니다.
- `tools/art/gen-illust.mjs`는 Gemini REST API를 호출합니다. 도트 초상을 참고 그림으로 함께 보내 같은 캐릭터를 유지합니다.
- 기본 모델은 `gemini-3.1-flash-image`이며 `--model`로 바꿀 수 있습니다. `--only`, `--force`, `--dry` 옵션이 있습니다.
- 결과는 `client/public/assets/illust/<id>.png`와 `index.json`에 저장됩니다.
- `?illust` 주소로 열리는 테스트 페이지에서 전체 인물 카드를 확인하고, 카드를 누르면 실제 대화창으로 미리 볼 수 있습니다.
- 생성 스크립트는 샌드박스에서 실제 API를 호출해 보지 못했습니다. 응답 구조도 확인하지 못해서 폴백 로직을 넣어 두었습니다.
- 사용자는 이후 Gemini에서 직접 그림을 그리기로 했습니다. 완성된 그림은 같은 폴더에 넣고 `index.json`에 등록하면 게임에 반영됩니다.

## 7. 검증 상태

- 맵 생성, 워프, 도달성 검사는 통과했습니다.
- 관리자 권한과 `give` 보안 검사를 통과했습니다.
- 서버 WebSocket 테스트를 진행했습니다.
- Socket.io는 샌드박스에서 npm 레지스트리에 접근할 수 없어 설치하지 못했습니다. 타입 스텁으로 타입 검사만 했고, 실제 실행은 아직 하지 못했습니다.
- Azure와 Vercel 연결은 아직 확인하지 못했습니다.

## 8. 남은 작업

- 사용자 PC에서 `npm install`을 실행해 Socket.io를 설치합니다.
- 로컬에서 `npm run server`와 `npm run dev`를 함께 실행해 연결을 확인합니다.
- Vercel과 Azure 환경변수를 설정한 뒤 배포 주소로 연결을 확인합니다.
- Gemini 그림을 `client/public/assets/illust/`에 넣고 `index.json`에 등록합니다.
- 연결이나 설정 문제가 생기면 알려 주시면 이어서 고치겠습니다.
